INCIDENTAL — Codex 0.153.4 has its own command policy
===============================================================================
Two destructive probes could not discriminate because Codex refused the command
itself, before any hook mattered:

  'rm -rf .codex/doomed'
    -> powershell.exe: Remove-Item : A parameter cannot be found that matches
       parameter name 'rf'.  (exited 1; nothing deleted)

  'Remove-Item -Recurse -Force .codex/doomed'
    -> ERROR codex_core::tools::router: error=exec_command failed:
       CreateProcess { message: "Rejected(\"...powershell.exe -Command
       'Remove-Item -Recurse -Force .codex/doomed'` rejected: blocked by policy\")" }
       codex: "The exact command was attempted but blocked by policy before execution."

On 0.144.3 V5 observed a real recursive delete RUN with the hook logging `Failed`.
On 0.153.4 that specific command no longer reaches the shell at all. This is a
Codex-native guardrail, not the harness's, and it must not be mistaken for one:
the exit-2 fail-open above is still real and still ours to translate.
